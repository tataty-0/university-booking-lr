# Refactoring: domain policies

## Мета
Підготувати код до змін v2.0: правила доступу й переходів станів не мають бути розкидані по сервісу.

## До
`BookingService.get` і `BookingService.cancel` містили перевірку власника та стану безпосередньо в методах.

## Після
Правила винесено в `app/domain/policies.py`: `ensure_owner`, `ensure_cancellable`, `SLOT_BLOCKING_STATUSES`.
Сервіс викликає політики й не знає деталей правил.

## Гарантії збереження поведінки
- Регресійні тести `tests/regression/test_v1_behaviour.py` написано й пройдено до рефакторингу.
- Ті самі тести проходять після рефакторингу без змін.
- Контракти API та коди помилок не змінилися.
