# ADR-002: Захист від подвійного бронювання

## Контекст
Два паралельні запити на перетинні інтервали не мають створити два активні бронювання.

## Альтернативи
1. Транзакція `BEGIN IMMEDIATE` з перевіркою конфлікту перед вставкою.
2. Блокування на рівні застосунку (mutex у процесі).
3. Обмеження в БД (exclusion constraint) — недоступне в SQLite.

## Рішення
Для кожного створення відкривати `BEGIN IMMEDIATE`, перевіряти конфлікти й вставляти запис в одній транзакції.

## Переваги
Коректно навіть для кількох процесів, не залежить від пам'яті процесу.

## Недоліки
Записи серіалізуються; можливі короткі очікування блокування (потрібен `busy_timeout`).

## Тригер перегляду
Міграція на СУБД з exclusion constraints або зростання навантаження на запис.
