# Вимоги до сервісу бронювання аудиторій

## Огляд продукту
Сервіс дозволяє студентам і викладачам переглядати аудиторії, перевіряти їх доступність, бронювати та скасовувати бронювання. Дані навчальні (синтетичні), користувачі підготовлені заздалегідь.

## Зацікавлені сторони
| Сторона | Інтерес |
|---|---|
| Користувач (студент/викладач) | швидко знайти й забронювати вільну аудиторію |
| Адміністратор (v2.0) | контролювати бронювання великих аудиторій |
| Команда супроводу | відтворюваний запуск, зрозумілі логи й помилки |

## Функціональні вимоги v1.0
| ID | Вимога |
|---|---|
| FR-01 | Перегляд аудиторій і їх доступності |
| FR-02 | Створення бронювання |
| FR-03 | Перегляд власних бронювань |
| FR-04 | Скасування власного бронювання |

## Бізнес-правила
1. Початок бронювання передує кінцю.
2. Інтервали піввідкриті: [start, end).
3. Суміжні інтервали дозволені (кінець одного дорівнює початку іншого).
4. Перетин активних бронювань однієї аудиторії заборонений.
5. Паралельні запити не можуть створити подвійне бронювання.
6. Бронювання зберігаються після перезапуску сервісу.
7. Користувач бачить і змінює лише власні бронювання.
8. Помилки валідації, конфлікту, доступу та технічні відрізняються кодом відповіді та кодом помилки.
9. Час приймається лише з часовим поясом і зберігається в UTC.

## Критерії прийняття
| FR | Критерій |
|---|---|
| FR-01 | Список аудиторій містить назву та місткість; перевірка інтервалу повертає конфлікти |
| FR-02 | Валідний запит створює бронювання; start >= end → 422; перетин → 409; суміжне бронювання → 201 |
| FR-03 | Видно лише бронювання поточного користувача |
| FR-04 | Власник скасовує; інший користувач → 403; слот звільняється |

## Якісні вимоги
| ID | Вимога | Середовище | Метод вимірювання | Поріг |
|---|---|---|---|---|
| QR-01 Контроль доступу | Скасування чужого бронювання неможливе | CI, тестова SQLite | тест з двома користувачами | 100% спроб відхилено (403), 0 змін у БД |
| QR-02 Збереження даних | Бронювання переживають перезапуск | локально, файлова SQLite | створити, перезапустити застосунок, прочитати | 100% записів збережено |
| QR-03 Продуктивність | Створення бронювання відповідає швидко | CI, 200 послідовних запитів | p95 тривалості в тесті | p95 ≤ 200 мс |

Пороги задано до вимірювання; результати фіксуються в «Quality Verification».
